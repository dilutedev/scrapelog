scrapelog ingest API

This API stores one record for every HTTP request your scraper makes: the URL, the status, the latency, the proxy, the error and so on. The operator views the records in dashboards. This page tells you everything you need to send records correctly. Every limit on this page is read from the running server, so it is always current.

Base URL{{.BaseURL}}
FormatJSON (UTF-8). Batch requests send a JSON array; stream requests send one JSON object per line.
AuthenticationAuthorization: Bearer <your ingest key> on every request except /v1/health and /docs.
Endpoint to usePOST {{.BaseURL}}/v1/requests unless you have a reason to stream.

1. Your ingest key

  • The operator creates the key and gives it to you. You cannot create keys yourself.
  • A key looks like sl_ + 12 characters + _ + 43 characters, for example sl_AbCdEf123456_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx. Send the whole string.
  • A key belongs to exactly one project. Every record you send is stored under that project. You do not send a project name, and if you put a project field in a record it is ignored.
  • Treat the key as a password. Load it from an environment variable or a secret store and never commit it. If it leaks, ask the operator to revoke it and issue a new one. A revoked key stops working within 35 seconds.
  • One key per scraper is a good default, because the rate limit is counted per key.

All examples on this page read the key and base URL from these variables:

export SCRAPELOG_URL={{.BaseURL}}
export SCRAPELOG_KEY=sl_...
Send a User-Agent header naming your client, for example User-Agent: scrapelog-client/1.0. The proxy in front of this API may block some library defaults: Python's built-in urllib (Python-urllib/3.x) is answered with 403 error code: 1010 before the request reaches the API.

The header is exactly Authorization: Bearer followed by the key, with one space and the word Bearer capitalised as shown. A missing, malformed, unknown or revoked key gets:

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer

{"error":"unauthorized"}

2. Send your first record

curl -sS -X POST "$SCRAPELOG_URL/v1/requests" \
  -H "Authorization: Bearer $SCRAPELOG_KEY" \
  -H "Content-Type: application/json" \
  -d '[{"url": "https://example.com/products?page=2", "method": "GET", "status": 200, "latency_ms": 412}]'

Expected response, status 200:

{"accepted":1,"rejected":0,"errors":[],"warnings":[]}

Then confirm it was stored:

curl -sS -H "Authorization: Bearer $SCRAPELOG_KEY" "$SCRAPELOG_URL/v1/stats"

row_count goes up by one. If it does, your setup is correct.

3. What to send

Send one record for every HTTP request attempt your scraper makes, including attempts that failed.
  • Successful response (any status, including 4xx and 5xx): set status to the response status code.
  • No response (timeout, DNS failure, connection refused, TLS error, proxy error): set status to 0 and put the error text in error.
  • Retries inside your scraper: each attempt is its own record with its own request_id. Use tags (for example {"attempt": "2"}) if you want to link attempts.
  • A record counts as an error in the dashboards when status is 0 or error is not empty. So a 403 with an empty error is not an error; a 200 with "error": "captcha page" is.
  • Collect records in memory and send them in batches (for example every 1 to 5 seconds, or every 500 to {{.MaxBatchRecords}} records). Do not make one API call per record.

4. Record fields

A record is a JSON object. Only url and method are required. Rules that apply to every field:

  • Fields not listed below are ignored, not rejected. Check spelling: a misspelled field such as latency is silently dropped.
  • A field that is missing or null gets its default. An empty string also gets the default, except for ts: "ts": "" is rejected, so leave ts out instead.
  • Types are strict. "status": "200" (a string) is rejected; send "status": 200. Strings are never converted to numbers and numbers are never converted to strings.
  • If a record breaks any rule below, that record is rejected and the others in the request are still stored. See the response summary.

6. Batch endpoint: POST /v1/requests

The default way to send records.

URLPOST {{.BaseURL}}/v1/requests
HeadersAuthorization: Bearer <key> (required)
Content-Type: application/json (recommended)
Content-Encoding: gzip or zstd (optional, see limits)
BodyA JSON array of record objects: [{...}, {...}]. Always an array, even for one record.
Max records{{.MaxBatchRecords}} per request
Max size{{.MaxRequestBytes}} bytes ({{mebibytes .MaxRequestBytes}} MiB) as sent; {{.MaxDecodedBytes}} bytes ({{mebibytes .MaxDecodedBytes}} MiB) after decompression
ResponseA summary object

What happens to a batch

A batch fails as a whole, with nothing stored, in these cases:

  • The body is not valid JSON anywhere in it, including one malformed element ([{"url": ...}, {bad json}]). Response: 400 {"error":"invalid request body"}.
  • The body is a JSON object instead of an array. Response: 400 {"error":"body must be a JSON array of records; wrap a single record in [ ]"}.
  • It has more than {{.MaxBatchRecords}} records, or is too large (413); uses an unsupported Content-Encoding (415); has an invalid gzip body (400).
  • The key is missing or invalid (401), the rate limit is reached (429), or the server's storage budget is full (507).

Otherwise each record is checked on its own:

  • Valid records are stored. Invalid records are rejected and listed in errors with their position in your array.
  • If at least one record was stored: status 200.
  • If no record was stored (every record invalid, or the array was empty []): status 400, still with a summary body.
A 200 does not mean every record was stored. Always check rejected and errors.

7. Stream endpoint: POST /v1/requests/stream

Use this only if your scraper produces a continuous flow of records and you want to send them over one long request instead of many batches. If unsure, use the batch endpoint.

URLPOST {{.BaseURL}}/v1/requests/stream
HeadersAuthorization: Bearer <key> (required)
Content-Type: application/x-ndjson (recommended)
Transfer-Encoding: chunked (so you can write while sending)
Content-Encoding: gzip or zstd (optional)
BodyNewline-delimited JSON: one record object per line, each line ending in \n. No surrounding array, no commas between lines.
Max line size{{.MaxRequestBytes}} bytes per line. There is no limit on the number of lines.
DurationEnd each stream and start a new one at least every 60 seconds. Proxies in front of this API close requests after about 100 seconds; a closed stream loses its summary.
ResponseA summary object, sent once, after you end the request body
{"url":"https://example.com/a","method":"GET","status":200,"latency_ms":120}
{"url":"https://example.com/b","method":"GET","status":0,"error":"timeout","latency_ms":30000}

How the stream differs from a batch

  • Records are stored while the stream is open, in groups: every {{.StreamFlushLines}} lines or every {{.StreamFlushSeconds}} seconds, whichever comes first.
  • A line that is not valid JSON rejects only that line (record is not valid JSON); the stream continues.
  • Empty lines are skipped and do not count.
  • index in errors and warnings is the line number, starting at 0 and counting only non-empty lines.
  • The errors and warnings lists hold at most {{.MaxBatchRecords}} entries each; rejected is always the full count.
  • If storing a group fails (rate limit, storage budget, server error), the stream stops. The response has the failure's status code, an error field, and a summary of everything stored before the failure.
After a stream fails, lines 0 to accepted + rejected - 1 are finished (stored or rejected). Resend from line accepted + rejected onward.
HTTP/1.1 429 Too Many Requests
Retry-After: 3

{"accepted":4000,"rejected":0,"errors":[],"warnings":[],"error":"rate limit exceeded"}

Here lines 0 to 3999 are stored. Wait 3 seconds and resend from line 4000.

8. The response summary

Both ingest endpoints answer with this object (status 200, or 400 when nothing was accepted):

{
  "accepted": 998,
  "rejected": 2,
  "errors": [
    {"index": 4, "error": "url is required"},
    {"index": 9, "error": "status must be a int"}
  ],
  "warnings": [
    {"index": 7, "warning": "body upload failed"}
  ]
}
FieldMeaning
acceptedNumber of records stored.
rejectedNumber of records not stored because they were invalid. accepted + rejected equals the number of records you sent.
errorsOne entry per rejected record. index is the record's position in your array (batch) or its line number (stream), starting at 0. error says what is wrong. Rejected records are not stored; fix them before resending, or drop them.
warningsOne entry per record that was stored but whose response body was not. Do not resend these records. See bodies.
errorStream only, present only when the stream stopped early. Why it stopped.

Every other error response is {"error": "<message>"}.

11. Rate limit

  • Each key has a budget of {{.RecordsPerMinute}} records. It refills continuously at {{.RecordsPerSecond}} records per second, up to the full budget.
  • A batch takes as many records from the budget as it has valid records. If the budget is too small for the whole batch, the batch gets 429 and nothing is stored; it is never partly stored because of the rate limit.
  • Retry-After is the number of whole seconds until the budget is large enough for that batch. Wait at least that long before resending.
  • The limit is per key. Separate keys for separate scrapers do not slow each other down.

12. Retries and duplicates

The API does not remove duplicates. If you send the same record twice, it is stored twice, even with the same request_id.

Retry rules:

  1. Set request_id on every record before the first attempt, and keep the same value on every retry. Then any duplicates share a request_id and can be told apart from real repeat requests.
  2. Retry only on 429, 503, 502, 504, 520-524 and network errors. Never retry 400, 401, 413 or 415 unchanged.
  3. Wait Retry-After seconds when the header is present; otherwise back off (for example 1, 2, 4, 8, 16 seconds).
  4. Give up after about 5 attempts and log the failure. Your scraper should keep working even if this API is down: do not block scraping on delivery.
  5. On a 200, never resend, even if some records were rejected. Resending would duplicate the accepted ones.

13. Redaction and privacy

  • These header names are redacted in both request_headers and response_headers, matched case-insensitively. Their values are stored as [REDACTED]:
      {{range .RedactedHeaders}}
    • {{.}}
      • {{else}}
    • none
      • {{end}}
  • A username and password in url or proxy are removed.
  • Nothing else is redacted. Query strings, tags, error, request bodies, response bodies and all other headers are stored exactly as sent, and anyone with dashboard access can read them.
  • Do not send API tokens, session tokens, passwords or personal data in URLs, tags, bodies or non-redacted headers. Remove them in your scraper before sending.

14. Request and response bodies

request_body: what your scraper sent

  • Stored in the database and shown in the dashboards' request explorer.
  • Over {{.MaxBodyBytes}} bytes (measured after base64 decoding) rejects the whole record with request_body exceeds MAX_BODY_BYTES ({{.MaxBodyBytes}} bytes). Bodies are never cut short. Drop or shorten the body yourself if it may be large.

body: the response you received

    {{if .BodyStorageEnabled}}
  • Response bodies are stored on this server. Each body is compressed and kept in object storage, linked to its record.
    • {{else}}
  • Response bodies are not stored on this server right now. Records with a body are stored without it and get the warning body dropped: S3 is not configured. Leave body out to save bandwidth unless the operator tells you otherwise.
    • {{end}}
  • A body that cannot be stored never rejects its record. The record is stored and a warnings entry says why the body is missing: body dropped: S3 is not configured, body upload failed, body upload timed out, or body exceeds MAX_BODY_BYTES ({{.MaxBodyBytes}} bytes). Do not resend those records.
  • An invalid body_encoding or invalid base64 does reject the record.
  • Set a short request_id (only A-Z a-z 0-9 . _ -) on records with a body. It names the stored body file, and other characters are replaced with _, so two different ids could end up sharing a file.

15. Retention

  • Records with status 200 to 399 are deleted 14 days after their ts.
  • All other records (errors, 4xx, 5xx, status 0) are deleted 60 days after their ts.
  • Hourly totals in the dashboards are kept after the individual records are deleted.
  • The operator can change these periods.

18. Client examples

These use only each language's standard library. Each one sets request_id, compresses, and retries correctly.

Python 3

import gzip
import json
import os
import time
import urllib.error
import urllib.request
import uuid

SCRAPELOG_URL = os.environ.get("SCRAPELOG_URL", "{{.BaseURL}}")
SCRAPELOG_KEY = os.environ["SCRAPELOG_KEY"]
RETRYABLE_STATUSES = {429, 502, 503, 504, 520, 521, 522, 523, 524}


def send_batch(records, max_attempts=5):
    for record in records:
        record.setdefault("request_id", str(uuid.uuid4()))
    payload = gzip.compress(json.dumps(records).encode("utf-8"))

    for attempt in range(max_attempts):
        request = urllib.request.Request(
            SCRAPELOG_URL + "/v1/requests",
            data=payload,
            method="POST",
            headers={
                "Authorization": "Bearer " + SCRAPELOG_KEY,
                "Content-Type": "application/json",
                "Content-Encoding": "gzip",
                "User-Agent": "scrapelog-client/1.0",
            },
        )
        try:
            with urllib.request.urlopen(request, timeout=60) as response:
                summary = json.load(response)
                for rejection in summary["errors"]:
                    print("scrapelog rejected record", rejection["index"], rejection["error"])
                return summary
        except urllib.error.HTTPError as http_error:
            if http_error.code not in RETRYABLE_STATUSES:
                raise RuntimeError(f"scrapelog {http_error.code}: {http_error.read().decode()}") from None
            time.sleep(int(http_error.headers.get("Retry-After") or 2 ** attempt))
        except (urllib.error.URLError, TimeoutError):
            time.sleep(2 ** attempt)
    raise RuntimeError(f"scrapelog: giving up after {max_attempts} attempts")

    {
        "url": "https://example.com/products?page=2",
        "method": "GET",
        "ts": "2026-11-08T14:03:07.123Z",
        "status": 200,
        "latency_ms": 412,
        "scraper": "products",
    },
])

Node.js 18 or newer

import { gzipSync } from "node:zlib";
import { randomUUID } from "node:crypto";

const SCRAPELOG_URL = process.env.SCRAPELOG_URL ?? "{{.BaseURL}}";
const SCRAPELOG_KEY = process.env.SCRAPELOG_KEY;
const RETRYABLE_STATUSES = new Set([429, 502, 503, 504, 520, 521, 522, 523, 524]);

async function sendBatch(records, maxAttempts = 5) {
  for (const record of records) record.request_id ??= randomUUID();
  const payload = gzipSync(JSON.stringify(records));

  for (let attempt = 0; attempt < maxAttempts; attempt++) {
    let response;
    try {
      response = await fetch(`${SCRAPELOG_URL}/v1/requests`, {
        method: "POST",
        headers: {
          Authorization: `Bearer ${SCRAPELOG_KEY}`,
          "Content-Type": "application/json",
          "Content-Encoding": "gzip",
        },
        body: payload,
        signal: AbortSignal.timeout(60_000),
      });
    } catch {
      await new Promise((resolve) => setTimeout(resolve, 2 ** attempt * 1000));
      continue;
    }
    if (response.ok) {
      const summary = await response.json();
      for (const rejection of summary.errors) console.warn("scrapelog rejected record", rejection.index, rejection.error);
      return summary;
    }
    if (!RETRYABLE_STATUSES.has(response.status)) {
      throw new Error(`scrapelog ${response.status}: ${await response.text()}`);
    }
    const waitSeconds = Number(response.headers.get("Retry-After")) || 2 ** attempt;
    await new Promise((resolve) => setTimeout(resolve, waitSeconds * 1000));
  }
  throw new Error(`scrapelog: giving up after ${maxAttempts} attempts`);
}

await sendBatch([
  { url: "https://example.com/products?page=2", method: "GET", status: 200, latency_ms: 412, scraper: "products" },
]);
